# BE-002 — Repository / Version / Evidence / Audit Foundation

Documentation status: pre-implementation

## Task ID

BE-002

## 背景

PR Review 需要可持久化业务对象边界，支持 Case、不可变 ContentVersion、审核结果、EvidenceSnapshot 与 append-only Audit Action。ALG-004 的版本化 Evidence RAG 依赖稳定 repository/evidence snapshot port。

## 当前行为

- Algorithm 可以输出审核结果，但没有业务 repository port。
- 内容修改、审核结果、证据快照、人工动作尚无统一生命周期。
- 无法保证历史审核 replay 时使用的知识与证据可解释。

## 期望行为

冻结并实现：

- `ReviewCaseRepository`
- `ContentVersionRepository`
- `ReviewResultRepository`
- `EvidenceRepository`
- `ReviewActionRepository`

MVP 使用 InMemory adapter，但接口必须可替换为真实数据库实现。

核心原则：

- ContentVersion immutable。
- ReviewAction append-only。
- 通过 `expectedVersion` 做 optimistic locking。
- ReviewResult / EvidenceSnapshot 绑定 `caseId + version + executionId`。
- Revision transaction 必须原子化：校验版本、创建新版本、追加 action 要么全部成功，要么全部不产生可见副作用。

- `INVALID_STATE`

## 状态 / Schema 变化

`EvidenceSnapshot` 至少包含：

- `snapshotId`
- `caseId`
- `version`
- `executionId`
- `knowledgeVersion`
- `socialContextVersion`
- `evidenceItems`
- `createdAt`

`ContentVersionRecord` 不允许更新正文。修改正文只能创建 `version + 1`。

`ReviewActionRecord` 只能追加，不提供 delete/update mutation。

## 校验规则

- `caseId`、`versionId`、`snapshotId`、`executionId` trim 后不能为空。
- `version` 与 `expectedVersion` 必须为正整数。
- `createdAt` 必须为有效 ISO-8601 timestamp。
- `knowledgeVersion` 与 `socialContextVersion` 允许为 `null`，但字段必须存在。
- InMemory adapter 返回对象副本，调用方不能通过引用修改内部状态。

## 错误处理

- version conflict 必须显式返回/抛出 typed repository error。
- transaction 失败不得留下新 ContentVersion 或半条 ReviewAction。
- evidence snapshot 不存在时返回 `NOT_FOUND`，不得用空 snapshot 伪装成功。

## 测试计划

- 创建 case 与 initial version。
- ContentVersion immutable。
- ReviewAction append-only。
- optimistic locking conflict。
- result/evidence 绑定 `caseId + version + executionId`。
- EvidenceSnapshot replay 字段完整。
- revise transaction 成功时 version + action 同时存在。
- revise transaction 失败时无半成品。
- repository 返回副本，外部 mutation 不污染内部状态。

## 验收标准

- BE-002 focused repository tests 通过。
- Repository port 不 import Algorithm graph internals。
- BE-002 完成后解除 ALG-004 的 repository/evidence snapshot 依赖。

## 非目标

- 不实现真实数据库。
- 不实现 Auth。
- 不实现分布式事务。
- 不实现 durable checkpoint。
- 不实现 Publisher。

## Implementation Result

完成 Repository / Version / Evidence / Audit Foundation：

- 新增 repository record schemas：ReviewCaseRecord、ContentVersionRecord、StoredReviewResult、EvidenceSnapshot、ReviewActionRecord、RevisionTransactionInput/Result。
- 新增 repository ports：ReviewCaseRepository、ContentVersionRepository、ReviewResultRepository、EvidenceRepository、ReviewActionRepository、RevisionTransactionRepository。
- 新增 InMemory adapter。
- ContentVersion 只追加，不覆盖旧正文。
- ReviewAction append-only。
- REVISE 使用 `expectedVersion` 乐观锁，并以 transaction-like 流程同成同败地创建新 version 与 action。
- EvidenceSnapshot 绑定 `caseId + version + executionId + knowledgeVersion + socialContextVersion + evidenceItems`。
- Repository 返回冻结副本，外部 mutation 不污染内部状态。
