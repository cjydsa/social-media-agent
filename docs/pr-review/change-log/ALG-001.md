## 实现前设计（Pre-Implementation Design）

### 任务编号（Task ID）

ALG-001 — 冻结领域 Schema 与 ReviewEngine Port

### 背景（Background）

Phase 0 已通过文档和 TypeScript 形式的示例冻结 PR Review 公共对象，DATA-001 也以纯文档方式冻结了 Social Data 边界。后续 Backend 与 Algorithm 工作在进入 graph、reviewer、routing 或持久化实现前，需要一套唯一、可在运行时验证的公共合同。

### 当前行为（Current behavior）

`src/pr-review/algorithm/` 目前只有 Phase 0 骨架和 INFRA-001/002 provider factory。仓库尚无公共 Zod 领域 schema、`ReviewEngine` port、基于正文的 text span 上下文验证器、公共 typed failure，也没有 Social Data runtime schema 或 `SocialContextProvider` port。Architecture 已列出审核阶段，但 Contracts 仍将 `ReviewCase.currentStage` 写成 `string`，且未完整定义 ReviewEngine 输入/输出。

### 期望行为（Desired behavior）

- strict Zod schema 是 runtime 唯一事实源，TypeScript 领域类型一律由 `z.infer` 推导。
- 严格按 Contracts 冻结并导出 `ContentType`、`ReviewDecision`、`RiskLevel`、`IssueCategory`、`Severity`、`ReviewerType`、`ReviewActionType`、`ReviewStage`、`ReviewCase`、`ReviewResult`、`ReviewIssue`、`EvidenceItem` 和 `ReviewAction`。
- 提供显式 `validateReviewResultAgainstContent(result, currentContent)` helper，验证 standalone `ReviewIssueSchema` 无法真实验证的 UTF-16 `[start,end)` 上界与 quote 一致性。
- 冻结 `ReviewEngineInput`、runtime `ReviewContext`、`ReviewEngineOutput`、`ResumeReviewInput`、`InterruptDescriptor`、`ExecutionReference`、`ReviewFailure` 和 `ReviewEngine` public port，但不实现 workflow 行为。
- 实现 DATA-001 的纯 Social Zod schemas（包括命名导出的 `SocialMediaType` 与 `SocialProviderStatus`）和 Algorithm-facing `SocialContextProvider` port；将 `SocialDataAdapter` runtime port/实现和所有平台 Adapter 留给 DATA-002。
- `src/pr-review/algorithm/index.ts` 只导出稳定合同，不导出 graph/reviewer/routing internals。

### 接口变更（Interface changes）

公共 barrel 将导出 Zod schemas、由其推导的 types、`ReviewEngine`、`SocialContextProvider` 和 ReviewResult 上下文验证器。`ReviewEngine` 仅包含 `review(input, context)` 与 `resume(input, context)` 两个返回 `Promise<ReviewEngineOutput>` 的方法；本轮不新增实现类。

`ReviewContext` 是 Algorithm runtime context，不是 JSON 或 HTTP context。其 strict top-level contract 包含非空 `requestId`、nullable ISO deadline、仅允许已脱敏 scalar 的 trace metadata map、nullable cancellation capability，以及 strict dependency ports 中的 nullable `socialContextProvider`。它不得包含 Express request/response、database client、Frontend state、credentials、正文或 provider SDK client。

Social runtime 范围包括 DATA-001 enums、normalized objects、search input/result、context query/snapshot 的 schemas，以及 `SocialContextProvider`。`SocialDataAdapter` runtime port 和所有 adapters 继续归 DATA-002。

### 状态与 Schema 变更（State/schema changes）

- `ReviewStage` 冻结为 `REQUESTER_SELF_CHECK`、`OPERATOR_REVIEW`、`VISUAL_REVIEW`、`COMPLIANCE_REVIEW`、`RISK_ROUTING`、`MEDIA_MANAGER_APPROVAL`、`SCHEDULING`、`COMPLETED`、`REJECTED`、`ESCALATED`、`REVIEW_REQUIRED`。
- 所有 public object 和固定结构 nested object 都使用 strict validation，未知字段 fail。按设计为 map 的 `traceMetadata` 与 `ReviewFailure.details` 允许任意 key，但 value 必须符合 scalar/JSON 约束。
- `ReviewEngineInput` 是 Algorithm 当前版本的不可变 snapshot，字段为 `caseId`、`version`、`contentType`、`targetPlatform`、`currentContent`、`imageUrls`、`currentStage`、`policyVersion`。它不包含 `originalContent`、HTTP state 或 database access，因为 ALG-001 仅审核当前版本。
- `ReviewEngineOutput` 包含 `caseId`、`version`、`results`、nullable `aggregateResult`、`nextStage`、`requiresHuman`、nullable `interrupt`、`execution` 和 `failures`。nullable aggregate 用于表示聚合前即失败；本轮不计算 ALG-003 aggregate。
- Resume input 使用 strict discriminated union：`REVISE` 要求非空 `revisedContent`；`APPROVE`、`REJECT`、`ESCALATE` 要求 `revisedContent: null`。全部 variant 都携带 execution/case/version、actor 和非空 reason。
- Interrupt type 本轮只冻结 `HUMAN_REVIEW`，并包含 stage、允许的人工 actions、非空 reason 和 required role。
- Execution reference 为 `executionId`、`threadId` 和 nullable `runId`；本轮不创建 checkpoint。
- Social normalized objects 严格遵循 Contracts 第 6 节。计数类字段是非负整数或合同允许的 `null`；固定 nested objects strict，所有时间字段都必须通过验证。

### 验证规则（Validation rules）

- ID 为字符串，trim 后不得为空；ID schema 返回 trim 后的值。
- timestamp 必须是带显式时区的有效 ISO-8601 timestamp；冻结 JSON 约定仍为 UTC。
- `version` 是整数且 `version >= 1`。
- `confidence` 是闭区间 `[0,1]`；evidence `score` 是 `null` 或闭区间 `[0,1]`。
- `latencyMs >= 0`；`inputTokens`/`outputTokens` 是非负整数；`estimatedCost` 是 `null` 或 `>= 0`。
- `ReviewIssue.textSpan.start/end` 是整数；`start >= 0` 且 `end > start`。
- text span 使用 JavaScript/JSON UTF-16 code unit 和左闭右开 `[start,end)` 语义。
- standalone `ReviewIssueSchema` 只验证 span 结构。`validateReviewResultAgainstContent` 先验证 ReviewResult schema，再对每个 non-null span 要求 `end <= currentContent.length` 且 `quote === currentContent.slice(start,end)`；失败返回带 path 的 Zod validation issue，不伪造 standalone schema 的上下文能力。
- `ReviewAction` 对 `REVISE` 强制要求 non-null versions 且 `toVersion === fromVersion + 1`。
- Social engagement/count 在已知时必须是非负整数；unknown 保留 `null`，不 coercion 为 0。

### 错误处理（Error handling）

公共 `ReviewFailureCode` 冻结为 `INVALID_INPUT`、`SCHEMA_VALIDATION_FAILED`、`DEPENDENCY_UNAVAILABLE`、`TIMEOUT`、`CANCELLED`、`REVIEWER_FAILED`、`INTERNAL_ERROR`。每项 failure 包含 `code`、非空 `message`、boolean `retryable`、typed `source` 和 nullable JSON `details`。Architecture 的具体 model/retrieval/visual/schema 原因映射到此公共 taxonomy；任何 failure 都不得转换为 APPROVE。Zod validation failure 保持结构化错误。本轮不实现 provider、model、graph、routing、reviewer、retry 或 aggregate 行为。

### 测试计划（Test plan）

TEST-001 将验证全部 enums、strict object/nested object、ReviewCase version/timestamp 边界、ReviewResult 数值边界、ASCII/中文/emoji UTF-16 span、quote/bounds failure、ReviewAction revision invariant、ReviewEngine public imports/schemas、typed failures、JSON round trip，以及本轮批准的 Social schemas/port。测试只使用 contract-only 或明确标记 synthetic 的 fixture。

### 验收标准（Acceptance criteria）

- Public enum、字段、nullability、stage 和 validation rule 与 Contracts 完全一致，不存在手写重复领域 interface。
- 每个固定 public object 层级的未知字段均 fail。
- UTF-16 contextual text span 验证正确，不能接受越界或 quote mismatch。
- Backend 未来可只导入 public ReviewEngine contract，无需接触 graph/reviewer。
- Typed failure 显式存在且不能隐含 approval。
- Social schemas 与 `SocialContextProvider` 已存在，但无 Adapter、connector、crawler、账号、网络或真实社媒数据。
- Prettier、TypeScript typecheck、TEST-001、现有 PR Review tests、docs checks 与 diff check 全部通过。

## 设计变更（Design changes）

### 2026-08-31 — Social 内联枚举命名澄清（非破坏性）

Accelerated Sprint 的 A3 明确要求 public exports 包含 `SocialMediaType` 与 `SocialProviderStatus`。DATA-001 已冻结两组取值，但原 Contracts 只以内联 union 表示。代码前将其命名为 public enum schema；取值、字段和 JSON 语义均不变化。已同步 Contracts、Algorithm/Test/Social Domain 和 TEST-001 测试矩阵。

同次代码前复核还将 `ReviewFailure.details` 引用的 `JsonValue` 递归结构显式写入 Contracts，消除 runtime schema 对 JSON-safe value 的实现歧义；未改变既定的 nullable details 语义。

### 2026-08-31 — 实现期 SocialSearchInput 边界澄清

首次实现后、最终 reconciliation 前发现：DATA-001 已把 empty query 定义为 future Adapter contract error，但 ALG-001 runtime validation 段没有明确 query/limit 的 schema 边界。立即停止代码收尾并追加决定：`query` trim 后非空，`limit` 为 `>= 1` 的整数，`timeRange` 只验证 timestamp、不增加顺序规则。同步 Contracts、Algorithm/Social/Test Domain 和 TEST-001 用例后重新过 Gate。另将实现中超出合同的 `sourceAdapter` 非空限制改回普通 `string`，避免无文档的过度验证。

实现中如发现其他必须改变的设计，须先在此追加记录并重新通过 Docs Gate。

## 实现结果（Implementation Result）

- 新增公共 Zod contract layer：8 个 PR Review enums、5 个命名 Social enums，以及 ReviewCase、ReviewResult、ReviewIssue、EvidenceItem、ReviewAction、ReviewEngine 与 Social 数据对象 schemas。
- 所有固定结构 public/nested objects 使用 strict validation；TypeScript domain types 均由对应 schema 的 `z.infer` 推导。
- 新增稳定 `ReviewEngine` port，只声明 `review`/`resume`；未实现 ReviewEngineImpl、graph、reviewer、rule、aggregate 或 routing。
- 新增 Algorithm-facing `SocialContextProvider` port；未实现 `SocialDataAdapter`、平台 Adapter、网络或数据采集。
- 新增 `validateReviewResultAgainstContent`，按 UTF-16 code unit、`[start,end)`、正文上界和 quote slice 执行上下文验证。
- 公共 typed failure 使用已冻结 code/source/details，strict schema 拒绝 `automaticApproval` 等 fail-open 扩展字段。
- public `src/pr-review/algorithm/index.ts` 仅导出稳定 schemas/types/ports/validator，没有导出未来 graph/reviewer internals。
