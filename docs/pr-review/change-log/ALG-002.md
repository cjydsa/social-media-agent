# ALG-002 变更日志

`Documentation status: pre-implementation`（文档状态：实现前设计）

## 实现前设计（Pre-Implementation Design）

### 任务编号（Task ID）

ALG-002 — Deterministic Multi-Agent LangGraph MVP

### 背景（Background）

PRODUCT-001 要求真实可运行的多智能体 orchestration，而不是单次 LLM 分类。ALG-001 已提供稳定 port 与 strict contracts；本任务在不调用真实模型/平台的条件下实现 graph、Planner、五 Specialist、Critic、Judge、Revision 和 in-memory HITL 基础。

### 当前行为（Current behavior）

不存在 ReviewEngine implementation、LangGraph state、agent nodes、parallel specialists、checkpoint、interrupt/resume 或 revision loop。

### 期望行为（Desired behavior）

- 使用 `@langchain/langgraph` StateGraph 与 MemorySaver。
- 节点：`input_validation`、`content_understanding`、`review_planner`、`evidence_planning`、五个 parallel specialist nodes、`evidence_critic`、`decision_judge`、`policy_guard`、`revision_agent`、`await_human_review`、`complete_review`。
- Planner 每次包含五维，至少 LIGHT；COMPLIANCE_SAFETY 不可跳过，可按 fixture/内容升级 FULL。
- 五 Specialist 是独立 deterministic agents，返回 DimensionReviewResult；fixture scenarios：normal、pr-risk、operations-risk、product-risk、customer-risk、compliance-risk、multi-risk、missing-evidence、reviewer-conflict、reviewer-failure。
- evidence tools 通过 ReviewContext optional ports/测试 mock 注入，graph state 只保存 evidence snapshot/IDs，不保存 provider clients。
- Critic 检查 evidence、unsupported conclusion、missing evidence 与冲突；Judge 产生 AI-style recommendation；Policy Guard 最终决定。
- MemorySaver 支持 interrupt/resume；REVISE 仅接受 Backend/user 提供的新正文，增加 revisionCount 后重跑，Revision Agent 本身不覆盖 currentContent。

### 接口变更（Interface changes）

新增 `createLangGraphReviewEngine(options)` 返回 ALG-001 `ReviewEngine` port。Scenario resolver 和 evidence tool mocks 是 composition/test dependencies，不写入 public business input。Backend 未来仍只依赖 `ReviewEngine`。

### 状态与 Schema 变更（State/schema changes）

Graph state 只保存 input、content understanding、plan、evidence items/IDs、dimension results、critic、judge、final decision、revision proposal、failures、revisionCount、execution 和 pending interrupt。dimension results/failures 使用 reducer；provider/context/client/Secret/HTTP/DB 不入 state。

### 错误处理（Error handling）

每个 agent output 经 frozen Zod schema parse。throw/invalid result/missing dependency/unexpected state 转 ReviewFailure；Policy Guard 强制 HUMAN_REVIEW/BLOCK，禁止默认 PASS。单个 specialist failure 不阻止其他 results 保留，但最终 fail closed。

### 测试计划（Test plan）

由 TEST-002 覆盖五维并行、Planner completeness、fixture scenarios、critic/judge/policy、interrupt/resume/revision、checkpoint/state isolation/determinism、invalid output 和无真实 API。

### 验收标准（Acceptance criteria）

- graph 真正由 LangGraph 编译并使用 MemorySaver。
- 五 Specialist 并行产生五个唯一 dimension results。
- Planner/Critic/Judge/Revision 均有独立结构化 contract/implementation。
- normal 可完成；风险/失败按 ALG-003 policy fail closed。
- interrupt/resume/revision 不无限循环，状态按 case/thread 隔离。

### 不在范围内（Out of scope）

真实 LLM、prompt engineering、RAG store、真实 evidence retrieval、OCR/VLM、Backend durable repository/outbox、Frontend、Publisher、生产 checkpoint、ALG-004。

## 设计变更（Design changes）

当前无设计变更；后续只允许追加。

## Implementation Result（实施结果）

2026-08-31 本轮完成 Deterministic Multi-Agent LangGraph MVP：

- 已实现基于 `@langchain/langgraph` 的 ReviewEngine implementation，并通过 ALG-001 public `ReviewEngine` port 暴露。
- Graph 节点已覆盖：input validation、content understanding、review planner、evidence planning、五个 specialist parallel review、evidence critic、decision judge、policy guard、revision agent、await human review、complete review。
- 五个 deterministic Specialist 已覆盖 `PUBLIC_RELATIONS`、`OPERATIONS`、`PRODUCT`、`CUSTOMER`、`COMPLIANCE_SAFETY`，并返回严格的 `DimensionReviewResult`。
- Planner 每次至少要求五个维度 LIGHT review，且不会跳过 `COMPLIANCE_SAFETY`；根据 fixture / 输入升级 FULL review。
- Evidence layer 使用 synthetic contract evidence 和 port boundary；Graph state 不保存 provider client、API key、HTTP request 或 DB client。
- MemorySaver checkpoint 已用于开发级 interrupt/resume；支持 APPROVE、REJECT、ESCALATE、REVISE 和 revision limit。
- reviewer throw / missing evidence / conflict / low confidence 等路径均 fail closed，不会自动 PASS。
