# BE-001 — Backend API Foundation

Documentation status: pre-implementation

## Task ID

BE-001

## 背景

PR Review 需要稳定 Backend API 边界，使未来 Frontend、CLI、WorkBuddy Adapter 与外部系统只通过 Backend DTO 访问审核业务，而不是直接依赖 Algorithm graph internals。

## 当前行为

- Algorithm 层已有 `ReviewEngine` port。
- Backend 尚未提供 PR Review API DTO、controller skeleton、错误 envelope 或分页合同。
- Frontend 未来缺少稳定 API 事实源。

## 期望行为

冻结并实现 Backend API MVP：

- `POST /api/reviews`
- `GET /api/reviews/:id`
- `GET /api/reviews`
- `POST /api/reviews/:id/approve`
- `POST /api/reviews/:id/revise`
- `POST /api/reviews/:id/reject`
- `POST /api/reviews/:id/escalate`
- `GET /api/reviews/:id/history`
- `GET /api/evaluations/latest`

BE-001 只建立 API 合同、DTO 校验、controller/handler skeleton、typed error envelope、pagination、request size 与 content-type 校验。

## 状态 / Schema 变化

- API 输入对象必须 strict。
- `CreateReviewRequest` 不包含 HTTP Request、数据库 client、provider secret 或 graph internals。
- 审核风险判断只能通过 `ReviewEngine` 或 service 注入的 stable port 执行。
- BE-001 本身不持久化数据；持久化由 BE-002 repository port 负责。

## 校验规则

- JSON request 必须使用 `application/json`。
- request body 不得超过 Backend 文档定义的 MVP 大小限制。
- `caseId`、`actor`、`reason` 等 ID / 文本字段 trim 后不能为空。
- `expectedVersion` 必须为正整数。
- pagination `limit` 有上限，`cursor` 为 opaque string。
- unknown fields 必须失败。

## 错误处理

Backend API 使用 typed error envelope：

- `VALIDATION_ERROR`
- `NOT_FOUND`
- `VERSION_CONFLICT`
- `UNSUPPORTED_MEDIA_TYPE`
- `PAYLOAD_TOO_LARGE`
- `METHOD_NOT_ALLOWED`
- `DEPENDENCY_UNAVAILABLE`
- `INTERNAL_ERROR`

错误响应不得包含 API key、provider secret、完整敏感正文或内部 stack trace。

## 非目标

- 不实现真实数据库。

- 不写 Prompt。
- 不直接 new DeepSeek/Qwen provider。
- 不实现风险判断逻辑。

- 新增 strict Zod DTO：create/list/action/revise/escalate/detail/history/error/pagination。

- API 层未导入 graph、prompt、reviewer internals，未实现风险判断。
