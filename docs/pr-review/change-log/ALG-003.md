# ALG-003 变更日志

`Documentation status: pre-implementation`（文档状态：实现前设计）

## 实现前设计（Pre-Implementation Design）

### 任务编号（Task ID）

ALG-003 — 五维评分、Decision Judge 与 Deterministic Policy Guard

### 背景（Background）

五维 Specialist 需要共同生成可解释的最终发布建议。纯 weighted average 会稀释 hard blocker；纯 if/else 又无法体现 Judge 对跨维语境、冲突和修改优先级的深度判断。

### 当前行为（Current behavior）

只有 legacy LOW/MEDIUM/HIGH ReviewResult，没有 0–100 dimension score、权重、Evidence Critic、Judge recommendation、FinalReviewDecision 或 hard gates。

### 期望行为（Desired behavior）

- 实现 PRODUCT-001 additive schemas：ReviewDimension、ReviewPlan、DimensionReviewResult、EvidenceCriticResult、JudgeRecommendation、FinalReviewDecision、ReviewPolicy、RevisionProposal。
- 默认权重：PR 0.25、Operations 0.15、Product 0.20、Customer 0.20、Compliance 0.20；仅为 configurable MVP defaults，不声明 benchmark 最优。
- 默认阈值：PASS overall `<=25`、all dimensions `<40`、confidence `>=0.75` 且 evidence complete；REVISE `26..49` 或可通过文字修复的 medium issue；不确定/缺证据/冲突进入 HUMAN_REVIEW；不可简单修复的 severe hard blocker 为 BLOCK。
- Judge 输入五维结果+critic+metadata，输出 recommendation/reason/top risks/revision priority；Policy Guard 可收紧但不可被 Judge 绕过。

文档：Contracts、Architecture、Algorithm/Test Domain、Plan/Board、本 Change Log。

### 接口变更（Interface changes）

ReviewEngineOutput 增加 optional `reviewPlan`、`evidenceCriticResult`、`judgeRecommendation`、`finalDecision`。ReviewContext dependency ports additive optional。旧 payload/type consumer 保持可用；multi-agent engine 成功执行时这些 v1.1 fields 必须存在。

### 状态与 Schema 变更（State/schema changes）

`riskScore/overallRiskScore` 为 `[0,100]`；confidence/coverage 为 `[0,1]`。Final decision 为 `PASS|REVISE|HUMAN_REVIEW|BLOCK`，与 legacy ReviewDecision 分离。Severity 增加 CRITICAL；IssueCategory/EvidenceSourceType additive 扩展并记录 exhaustive-consumer migration。

### 错误处理（Error handling）

Hard gates：CRITICAL issue、HIGH compliance、HIGH unsupported product claim、privacy/confidential leakage、reviewer failure 永不 PASS；required evidence unavailable/low confidence/conflict 超阈值进入 HUMAN_REVIEW。Weighted score 不能覆盖 hard gate。

### 测试计划（Test plan）

TEST-002 覆盖分数边界、权重和阈值、低 weighted score+hard blocker、Judge 不能越过 Guard、缺证据/低 confidence/冲突/失败、decision/publishable 一致性和 legacy contracts。

### 验收标准（Acceptance criteria）

- schemas strict，types 由 z.infer 推导。
- weights 总和 runtime 验证为 1，阈值可注入。
- normal PASS；hard blocker never PASS；不确定性 fail closed。
- Judge 与 Policy Guard 职责分离且均进入 traceable graph output。

### 不在范围内（Out of scope）

benchmark tuning、真实 model judge、最终法律判断、Backend organization policy persistence、生产实验配置和真实发布。
